## 0.5.0 - 2026-11-20

- The program has an icon: `mfi-wifi-setup/icon.ico` (generated by `tools/make_icons.py`, sizes 16, 32, 48 and 256) is built into the `.exe` by `build_windows.cmd` and set on the window (`mfi_wifi_setup/icon.py`, `window.py`). The build stops with a message when the icon file is missing; the window opens without the icon when it cannot be set.
- `tests/test_icon.py` checks the ICO format, the icon path, the generator output and the window code; `tests/test_build_script.py` checks the PyInstaller options.
- Program behaviour otherwise unchanged. Not tested on a device yet: ticket W3.

## 0.4.2 - 2026-11-17

- GitHub Actions workflow `.github/workflows/windows-exe.yml` (ticket T-MWKUB27O)
  builds the `.exe` on `windows-latest` with `build_windows.cmd`, checks that the
  `.exe` and its `.sha256` exist, and attaches both to each published release.
  Runs only on `workflow_dispatch` and on published releases; the `.exe` is never
  committed.
- `tests/test_windows_workflow.py` checks the workflow text (events, permissions,
  files, Python version) offline.
- `README.md` has a "Download" section with the hash check and the SmartScreen
  warning. The program code is unchanged. Not tested on a device yet: ticket W3.

## 0.4.1 - 2026-11-17

- Tests: `tests/test_version.py` compares `__version__` with the newest `CHANGELOG.md` entry instead of a hard-coded string. Version raised to 0.4.1 with the new `tools/bump_version.py`.

## 0.4.0 - 2026-11-17

- Windows build script `build_windows.cmd` (ticket W2 bis): one `.exe` with
  PyInstaller in one-file mode, `--windowed`, named
  `mfi-wifi-setup-<version>-windows-x64.exe`, with its `.sha256` file next to it.
  The script uses a temporary venv, removes it at the end and needs no
  administrator rights.
- PyInstaller pinned to `6.22.3` in `requirements-build.txt`: the latest release
  on PyPI (2026-09-12, Requires-Python >=3.8,<3.16), https://pypi.org/project/pyinstaller/.
- `tests/test_build_script.py` checks the script, the pin and the build ignores
  in the root `.gitignore`.
- README section "Build". The `.exe` is not built or tested on a device yet:
  ticket W3, a person.
- Program code unchanged.

## 0.3.0 - 2026-11-17

- Guided setup, version 2 of the window: the Wi-Fi network and its password are
  chosen in the program, not on the device page. The program lists the visible
  networks (open and WPA/WPA2 personal only), sends the chosen network and
  password to the device, and follows the progress on `status.cgi` until the
  address is obtained. Then it closes the device access point.
- New core modules without `tkinter`: `wifi_survey.py` (network list from
  `survey.json.cgi`, query for `captive.cgi`) and `wifi_configure.py` (setup
  states, configure, `leaveap.cgi` only on success).
- Version 1 (bridge to the original page) stays as the alternative.
- The controller fields of the device (`inform_addr`, `cloud_name`, `cloud_pass`)
  are not read, not shown and not sent.
- `tests/test_no_tkinter.py` checks the two new core modules too. Not tested on
  a device yet: the device test is ticket W3.

## 0.2.0 - 2026-11-17

- Version 1 of the program, from the verified prototype: a Windows window
  (`tkinter`, no console) with numbered steps, started with
  `python -m mfi_wifi_setup` from this folder. The `.exe` is not built yet
  (ticket W2).
- Core modules without `tkinter`: `bridge.py` (local bridge to the device page
  on 127.0.0.1, next free port when 8020 is busy), `device_check.py` (device
  state every 2 s), `messages.py` (Italian and English), `config_store.py` (the
  controller address only).
- Offline tests in `tests/` with the standard library: the core does not import
  `tkinter`, and the version matches this changelog.
- Specification in `docs/WIFI-SETUP.md`, version 0.2.0. The prototype
  `prototype/legacy_tls_proxy.py` is unchanged.

## 0.1.1 - 2026-11-17

- The program will be a graphical window (`tkinter`) with numbered steps, no
  console; specification 0.2.0 in `docs/WIFI-SETUP.md`. The prototype is
  unchanged.

## 0.1.0 - 2026-11-17

- Prototype `prototype/legacy_tls_proxy.py`: local bridge from the browser
  (plain http on 127.0.0.1) to the device setup page (TLS 1.0). Verified on an
  mPower mini with firmware v2.1.11: the setup page (36,535 bytes) and the JSON
  of `captivepoll.cgi`, `status.cgi` and `survey.json.cgi` come through; query
  strings are hidden in the log. Not verified yet: Apply (`captive.cgi`) and
  the switch of the device to the home network.
- Specification in `docs/WIFI-SETUP.md`.
